# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Chats that run themselves: a chat can be set to run with Codex CLI, Claude Code, GitHub Copilot CLI, Gemini CLI or a custom command. **Send** starts or continues the chat's session in its folder with the task prompt; the output streams into the task drawer; the task goes *in progress* on the first output, *done* from the report in the final message, or *waiting for your reply* when the agent asks something. **Reply** continues the same session, **Stop** ends a run.
- Per-chat run settings stored only on this computer (`~/.aitrack/runners.json`): CLI, working folder, access level (read only, edit files, full access), same session or a new one per task, session id (paste one to continue an existing chat), "don't wait for plan approval", network for the Codex sandbox, extra allowed tools, model, extra arguments, program path. CLIs are found on the login shell's `PATH` and the usual install folders.
- Auto-dispatch per project: free chats that run themselves get their most urgent ready task, up to a limit of runs at once.
- Hooks for sessions opened by hand: `POST /api/hook` understands Claude Code hook payloads and Codex `notify`, marks tasks in progress / waiting for your reply / done, and learns the session id so Send continues that conversation. `aitrack-report hook` forwards a hook without curl.
- A control token for the endpoints that start programs; the desktop app hands it to its windows and `aitrack serve` prints a link with it.
- Model and reasoning effort per chat, picked from lists: Codex's model catalog with each model's reasoning levels, Copilot's model list, and the Claude Code and Gemini aliases that follow the latest versions; any other model id can be typed. Model names with spaces are refused instead of failing at run time.
- Problems in reports: `issues` with a plain-language title, details, kind and a fix prompt. Prompts ask for them in the project's language; tasks with problems get a red **!** on cards, lanes, the Needs-you panel and the floating window, and the task drawer lists them with the fix prompt ready to edit, copy or send to the chat. Failures, decisions the chat waits for and tools a CLI refused show up there too.
- Your own prompts: add instructions to a task when sending it, write to a chat's session at any time, and keep a list of saved prompts to insert.
- Run details for chats that run themselves: live elapsed time, tool calls, tokens, turns, list price and how full the session's context is (Claude Code), on lanes, cards, the task drawer and the floating window.
- Info tips (ⓘ) next to auto-dispatch, the run limit, the run settings and the new panels; the sidebar folds into a rail (⌘B).
- Dark theme on a black ground with black-and-white components; status colours unchanged. Smaller corner radii. Clearer lane headers and floating-window rows.
- Event sources `runner` and `hook`. Runs interrupted by quitting the app are marked blocked on the next start.
- In-app updates on macOS: the app checks the git clone it was installed from (`git fetch`) when it opens and every 6 hours, shows **Update available** in the sidebar and the new commits under **Settings → Updates** (also **Check for Updates…** in the app menu), and **Update and restart** runs `update-macos.command` in the background: pull (fast-forward only), rebuild, replace the app and reopen it. Progress and the last lines of output are shown live; the new version says it was updated or why it failed. Optional: install new versions by itself when no chat is running. It asks before restarting while chats are running.
- The installer records where it was installed from in `~/.aitrack/install.json`; installer and updater run unattended with `AITRACK_UNATTENDED=1` and write their progress to `~/.aitrack/update-status.json` and `~/.aitrack/update.log`.
- Escape closes dialogs and settings.
- New project wizard: folder and name (with the plan's language), the chats (suggested from the AI CLIs found on this computer), and the plan — written by Claude Code, Codex, Gemini or Copilot running read-only in the folder, by any other AI (copy the instructions, paste the answer, check it), or left empty. The plan is shown before it is saved; problems in an AI's answer can be sent back to be fixed. New projects no longer start with placeholder chats and tasks; a project may have no chats or tasks (`agents` and `tasks` default to empty lists).
- Plan editor: add, change and remove tasks (chat, other chats that can take it, what it waits for — cycles are prevented —, prompts in order, instructions, acceptance, allowed paths, estimate, milestone, tags), a prompt library, project settings (name, description, language, approval), and Plan with AI for a project without tasks. Edits keep the file's formatting. **+ Task** in the header and in every lane; **Edit** in the task drawer.
- Project list: pin to the top, reorder by dragging or from the ⋯ menu, remove from the list or (desktop) move the file to the Trash. The order and pins are kept in the registry.
- A ten-step intro on first launch, available again from Settings.
- A project whose code folder (`settings.repoPath`) does not exist yet: the chat's run settings say so and offer the folder of the project file (or a folder picker), and Send explains what to do instead of "Working folder not found".
- When a chat's CLI is not installed, its run settings show the command that installs it (Claude Code, Codex, Copilot, Gemini) with a copy button, and Send says how to install it instead of only "was not found".
- A CLI that is installed but not signed in shows as "not signed in" with the command to run, instead of a fix prompt for the chat. A run that failed before the model answered no longer leaves a session id behind, so the next Send starts a new session instead of trying to resume one that does not exist; a session the CLI cannot find is forgotten too.
- Lower CPU and GPU use when idle: nothing on the board animates unless a chat is running, the running-chat indicator is drawn without repaints and stops while the window is in the background, the floating window's live blur follows its focus, and git worktrees are looked up once a minute instead of every 30 seconds.
- `make-dmg-macos.command`: double-click to build the app as a disk image (`release/AI-Tracking-System-<version>-<commit>-<arch>.dmg`, signed ad hoc on this Mac) and open it, then drag the app onto Applications. `install-macos.command` makes it with `AITRACK_TARGET=dmg`.
- Act from the floating window: clicking a chat or task opens its actions under the row — answer the chat or approve its plan, send a problem's fix, allow a refused command, mark a problem resolved or ignored, record a report that could not be read, stop the run, send, approve, mark done or reopen. **↗** still opens it in the main window.
- Stop a running chat from its lane, the floating window, the task drawer's live output, or all at once with **Stop all** next to automatic dispatch (`POST /api/projects/:key/runs/stop`); small stop buttons ask once more. Automatic dispatch no longer hands a chat you stopped its next task until you send it something; **Stop all** also switches automatic dispatch off.
- Claude Code with **Edit files** runs the usual work commands without asking — reading and searching, `mkdir`/`cp`/`mv`, local git, and build and test (`node`, `npm`, `make`, `go`, `python`…) — and can read the plan's repository when it works in another folder (`--add-dir`). An option in the run settings turns the commands off. A step it still refuses can be allowed from its problem.
- Problems can be marked **Resolved** or **Ignore**d in the task drawer; closed ones stop counting (no red **!**), are listed under *Resolved and ignored* and can be opened again. Recorded as a note in the task's history.
- A chat's message is shown as Markdown (headings, lists, tables, code, links), without the report JSON at its end. A report that arrived but could not be read can be recorded from the message with one click.
- Reports are read leniently: `"pr": null` and other `null` fields, unknown problem kinds, and a report written without the `aitrack-report` fence no longer leave the task "waiting for your reply". A note no longer replaces the chat's last message.
- The project's code folder: **Project settings → Code folder** changes where chats that run themselves work (stored relative to the project file; empty means the repository the file is in). When a plan points at a code folder that is not on this computer yet, the board says so and offers to create it as an empty git repository, choose another folder or use the plan's repository (`POST /api/projects/:key/code-folder`).
- No more whole-window flicker on macOS: opening the floating window no longer hides every window and the Dock icon for a moment, a window brought back from behind other windows keeps its page instead of drawing it again from empty, the native theme is set only when it changes, and pausing the running-chat indicator no longer restyles every element on each focus change. A request that fails for a moment or a project file caught while another program writes it keeps the board on screen instead of falling back to the welcome page.
- HTTP: `POST /api/projects/:key/tasks`, `…/tasks/:task/remove`, `…/prompts`, `…/prompts/:prompt/remove`, `…/info`, `…/plan`, `…/pin`, `POST /api/projects/order`, `POST /api/folder`, `POST /api/authoring/prompt`, `…/check`, `…/generate` (control token) with status and stop. The AI authoring instructions now live in `@aitrack/core` and are kept in sync with `docs/authoring-with-ai.md` by a test.
- README rewritten in English and Turkish for the new UI and features: what's inside, install, how updates work and troubleshooting, quick start, problems and run details, keyboard shortcuts, where data lives, roadmap; new demo recordings and an Updates screenshot.
- Claude Code chats with **Edit files** run in Claude Code's **auto mode** when the installed version has it: a safety check approves routine steps (looking around folders, reading details of this computer, running tests) and blocks risky ones, instead of refusing every step that is not on the allowed list. Edits inside the chat's folders need no review. When the CLI or the account cannot use auto mode, the run log says so and the next runs use the usual permissions; Claude Code that is too old for it is named in the run settings with `claude update`. A box in the run settings turns it off.
- The usual work commands also cover details of this computer (`uname`, `sw_vers`, `sysctl`, `system_profiler`, `ps`, `df`, `docker ps`/`info`, `brew list`…), `git remote` and `git config --get`. Claude Code may read its own notes for the working folder (`~/.claude/projects/<folder>/memory`).
- Refused steps on one card: *The chat skipped 3 steps it had no permission for*, each step with what it does in plain words and whether it only reads, makes changes or is risky. **Allow and continue** allows the safe ones for that chat — with a folder outside its own that they looked at, kept under the new *Other folders it may use* run setting — and tells the chat to go on where it stopped; risky ones need **Allow the risky ones too**. A task the chat finished anyway gets no such card.
- Decisions as buttons: a problem can carry `choices` (`label`, `reply`, `recommended`). The task drawer and the floating window show them as buttons; a click answers the chat in your language and closes the question. Chats that run themselves are told to find missing facts and take easy-to-undo choices themselves, to go on without a refused step, and to stop only for real decisions, asked in the project's language with options.
- The general *The chat is waiting for a decision* card is left out when the chat wrote down what it needs as problems of its own.
- A chat that must wait for another task reports `blocked` with `"waitingFor": ["<task id>"]` (`--waiting-for` in `aitrack-report`). The task shows as *waiting for …* with no problem and no red card, and the wait is written into the plan as a dependency. When the task it waits for is done, it is ready again for the same chat, ahead of its other work — sent at once with automatic dispatch, with a note of what was finished. A task waited for that was already done when the chat stopped leaves the task blocked for you.
- Several problems are closed in one request: `POST /api/projects/:key/tasks/:task/issues` with `{issues: [{index, title}], state}`.
- Work left for later: a report can carry `followUps` (`title`, `detail`, `agent`, `after`; `--follow-ups` in `aitrack-report`). Each becomes a **proposed task**, listed above the board and in the task drawer: **Add to plan** (a task `<task>-F1` for the chosen chat, after the task it came from), **Ignore** (and bring back), or **Fold into the current plan**: Claude Code, Codex, Gemini or Copilot reads the plan, the proposals and the open notes and answers with new tasks, links and proposals to drop; the app checks the answer (chats, dependencies, cycles) and shows it before writing it. Prompts now ask for problems only for what failed or what a person must do or decide; a `warning` is shown as a note that needs no answer.
- The **Manager**: a switch in the header hands a project to an AI CLI (for the night, say). It turns auto-dispatch on and does not poll: when a report or the end of a run leaves something new waiting for a decision (a failed run is tried again after 2, 5, 15 and 30 minutes; what it left for the person is not shown to it again until that task changes; a fixed guard of 30 runs an hour stops a loop), answers waiting chats, picks options, allows safe refused steps, parks tasks that wait for others, sends failed ones again, closes problems and folds proposals into the plan; with *Also approve finished work* (off by default) it approves finished tasks in review whose report shows them done, never ones with open problems. It never approves payments, enters credentials, accepts terms, publishes, deletes, pushes to a main branch or allows risky steps, and never touches chats run by hand; what it did and left for you is in its dialog and in each task's history (source `manager`). HTTP: `POST /api/projects/:key/manager`, `…/manager/run`, `…/proposals/add`, `…/proposals/state`, `…/proposals/integrate`, `…/proposals/preview`, `…/proposals/apply`.
- The desktop app keeps the computer from going to sleep on its own while chats run or a manager is on.
- Usage limits: when a CLI's plan limit runs out (Claude Code, Codex, Gemini, Copilot, rate limits), the run is not a failure. The task waits with the time it goes on, nothing new is sent to that CLI, the manager leaves it alone, and at the reset time the chat goes on by itself. The time is worked out once, never by trying again and again: from the CLI's message, Codex's own session records, or the plan (5 hours after the window's first run, midnight Pacific for Gemini's daily quota, the 1st for Copilot's monthly requests). The header badge and the manager's eye show the wait and where the time comes from; clicking the badge goes on now. Limits survive a restart.
- While a chat waits for its CLI's usage limit, the desktop app keeps the computer from going to sleep on its own, and the reset time is checked against the clock every minute and when the computer wakes, so a sleep does not delay the chats.
- Write to the manager from its eye: a message ("approve CLC-02", "tell Claude B to go on") makes it look at once, even when it is off; it acts on it within its rules (a message may ask it to approve finished work) and answers in the eye and in its log. `POST /api/projects/:key/manager/message`.
- The manager may close the problems of a finished task in review (work other tasks cover) and then approve it in the same look; before, closing them used up the task's one action and the approval was refused.
- **Full automation** for the manager (off by default): it reviews finished work itself — the change and its checks, with read-only `git` and `gh` commands when its CLI is Claude Code — sends work that is not done as asked back to its chat (at most twice), and approves work whose remaining gaps do not stop others (a skipped test, a check only a person can do), adding real remaining work to the plan. What it approved is listed under **Approved by the manager** in its dialog and in the eye, new ones marked, each with why and what you may want to look at. `POST /api/projects/:key/manager/approvals/seen`.
- **Full authority** for the manager (off by default): it decides as the person would instead of leaving it to them — grants the permissions chats ask for or that their problems show (full access too, when the chat's CLI has nothing finer), moves tasks to other chats (`assign`), takes duplicate tasks nobody started out of the plan (`drop`), has chats merge the green PRs a task needs (also other tasks'), continues stopped work and takes back what it left for the person. Payments, accounts, legal terms, deleting and publishing still stay with the person.
- Permissions read from the problem: a Codex or DeepSeek chat that did not name the permission its sandbox kept out (`ENOTFOUND`, `EPERM` on `127.0.0.1`, `Operation not permitted`) gets the **Allow from now on and continue** button anyway; allowing it settles every card the same permission covers, and with network already on the next step is full access.
- **Saving mode** (off by default): each task gets a conversation of its own instead of one that grows with every task the chat did (replies and resumes go on in it), and what chats checked (`facts` in reports) is kept and given to the next tasks so they do not check it again; **Facts** lists and removes them. `POST /api/projects/:key/facts/remove`.
- Antigravity CLI (`agy`) replaces Gemini CLI in the lists (a chat already set to Gemini CLI keeps it): print mode with JSON events, `--conversation` to go on, `--mode plan/auto` or `--dangerously-skip-permissions` for the access levels, `--add-dir`, `--model` and `--effort`. Its models are the ones the signed-in account's plan offers (`agy models`: Gemini, and on paid plans Claude and GPT), grouped by family in the run settings, which say when a list comes from the account. A run out of AI credits waits like any usage limit.
- More than one folder per chat: *Other folders it may use* is a list under the working folder (**Add folder** opens the folder dialog), and *Folders for every chat of this project* gives all chats of a project the same extra folders. Copilot now gets them as `--add-dir` and Gemini as `--include-directories`, besides Claude Code, Codex and DeepSeek.
- The manager's eye asks for input: **Waiting for you** lists what the manager left for the person and the permissions chats need that it may not give, with a count next to the eye; each line opens the task's card to answer it in place. Three looks for the eye: the green hologram, the Eye of Ra in black liquid glass (after the ancient Egyptian sign, white on black; its iris turns red when something is wrong), and white liquid glass.
- Plans stay smaller: the plan rules (manager and *Fold into the current plan*) no longer make a separate task to open, finish or merge a task's PR or check its own result, nor a follow-up of a follow-up's follow-up.
- **Merge green PRs into main** (off by default): a reviewed task's own chat merges that task's PRs when the checks are green — merge commit, no branch deleted, no force-push — once per task; Claude Code chats get the merge commands for that one reply only.
- A task parked until other tasks are done no longer holds its chat: the chat takes other ready tasks meanwhile (also the one it waits for, when that is its own), and the parked task comes back to it first, told to go back to its branch. Before, such a chat sat idle, and a chat waiting for its own work never moved. Lanes show these tasks under *Waiting for other tasks*.
- A chat that reports again with the same words is something new for the manager.
- DeepSeek CLI (DeepSeek Harness, `dsh`) as a chat runner and as a planning and manager CLI: its one-shot headless profile with JSON events, the task on standard input, the same Session through `--session-id`, `read-only` / `workspace-write` / `danger-full-access` for the three access levels, approvals refused (nobody can answer them) and shown as problems. The model and effort you pick go to it as a small `--patch` overlay; a worktree's shared `.git` folder is granted with *Edit files* so it can commit. Its rate limits wait minutes, not a plan window. A missing `DEEPSEEK_API_KEY` is explained.
- Permissions a chat asks for: a chat of any CLI names what it needs on a problem (`"permission": {"kind": "command" | "network" | "folder", "value": …}`), and **Allow from now on and continue** writes it into that chat's run settings for good — an *Extra allowed tools* entry for Claude Code and Copilot, Codex's network access, another folder for Claude Code, Codex and DeepSeek — then tells it to go on. What a CLI cannot allow on its own is offered as full access, behind a warning. Chats are told to ask this way instead of asking the person to run the step or writing scripts for them. Codex chats now get `--add-dir` for their other folders (and a worktree's shared `.git`). *Allow and continue* for Claude Code's refused steps now says it is for good.
- One eye for every project a manager runs: tabs at the top of its projection switch between them; a project with problems has a red **!** on its tab and turns the eye red while you look at another one; *Models at work* lists the chats of all of them, with the project's name. In the desktop app the eye follows the project open in the main window until you pick a tab.
- Planning a project already under way: the instructions for the AI plan only the work that is left (no tasks for finished work, half-done work as the missing part, a short check task when unsure), and `docs/authoring-with-ai.md` has steps an AI chat follows when it is only given the path of that file: find out where the project stands, show done / half done / left, ask what it cannot see, then write and check the file.
- A changed session prompt reaches the chats that go on with their conversation: their next task starts with the current version and a note that it changed (once; the tracker remembers which version each conversation read). Before, only new conversations saw it.
- The manager's eye can be dragged while it is open, too; on the board in a browser it can be moved as well, and stays where you leave it.
- Cursor CLI as a chat runner and as a planning and manager CLI: `cursor-agent` (or `agent`) in print mode with stream-json output, `--force --sandbox enabled` for *Edit files*, ask mode for read only, the same conversation through `--resume`, models from `--list-models`. Its usage limits are handled like the others.
- A task sent again after it was stopped, failed or interrupted continues the same conversation and is told to go on where it stopped; without a conversation, the chat first checks what is already done in the folder.
- The manager's eye: while a manager runs a project, a small animated eye pops up above all apps in its own transparent, always-on-top window in the desktop app (on the board in a browser); it can be dragged anywhere and remembers its place (it looks around, spins faster while the manager decides, turns red when something broke). Clicking it projects a panel downwards: the models at work (chat, CLI, model, task, last step, time), the project's progress, errors and problems, the latest news and the manager's last run; a click opens a line in place to read it whole, and its *Show in the app* button opens the task. A hide button appears on hover; the eye comes back from the Manager switch or when the manager is switched on again.

### Fixed

- The × of the task drawer and of dialogs closes them again in the desktop app: they lay over the window's drag strip, which took the click as a window move.
- Run details no longer show a Codex conversation's running total (or Claude Code's running cost) as what one run used.
- A chat moved to another CLI (Codex to Claude Code, say) no longer tries to continue the old CLI's conversation, which failed every run at once with `error_during_execution`: changing the CLI forgets its conversations, and a run whose conversation the CLI cannot find starts once in a new conversation instead of failing. A failure shows what the CLI wrote ("No conversation found …"), not only its code. The person is told: the task's history says the run started again in a new conversation; a chat whose saved conversation is another CLI's gets a red **!** on its badge and a warning with **Reset session id** in its run settings (also while the CLI is being changed there); and if starting over fails too, the task's problem card offers **Reset the session and send again**.

## [0.1.0] - 2026-11-12

### Added

- `.aitrack` project file format, version 1, with JSON Schema and validation (duplicate and unknown ids, cycles).
- Task graph: readiness by dependencies and chat capacity, layers, critical path, "why not now" reasons.
- Local tracker on `127.0.0.1:4317`: project registry, append-only event log, live updates over SSE.
- Agent reporting over HTTP, the zero-dependency `aitrack-report` CLI, inbox files (including git worktrees) and pasted `aitrack-report` blocks.
- UI with lanes per chat, flow by dependency step, list with filters, and a task drawer with the chat to send to, the rendered prompt and the full history. English and Turkish.
- Session prompts and quick prompts per chat; manual status changes, approval and notes.
- Export to `.aitrack` with an optional status snapshot; importing a snapshot is idempotent.
- Electron desktop app with `.aitrack` file association and installers via electron-builder.
- `install-macos.command`: double-click installer that builds the app, installs it in Applications and registers `.aitrack` files.
- Add, edit and remove chats from the app. A chat can be allowed to take the tasks of other chats; edits keep the project file's formatting and fields that were left out.
- Black liquid glass design: monochrome frosted surfaces, soft status colours, light theme in white glass; monochrome app icon.
- Screens built from panels (ready to send, chat lanes, flow, list, needs you, recent activity, progress): add, move by drag or arrows, resize, filter by chat; several named layouts, stored per user.
- Floating window: frameless, always on top, on every desktop, with project picker, overview / compact list / mini lanes, selectable sections and chats, one-click "copy & send", pin and opacity; opens tasks in the main window.
- Appearance settings: theme (dark, light, system), accent colour, density, text size and glass strength, shared live between windows.
- Glass that takes the tone of what is behind it: on macOS the main and floating windows are translucent (vibrancy) with the title bar hidden and the traffic lights in the sidebar; native materials follow the app theme. The dark palette is a warm neutral grey instead of black.
- `update-macos.command`: double-click updater that pulls from GitHub (fast-forward only, refuses local changes) and reinstalls only when there is something new.
- README rewritten with animated demos, theme-aware screenshots, Mermaid diagrams, install and update guides and the plan for automatic updates; Turkish README (`README.tr.md`).
- The UI follows the project's `settings.language` until a language is picked with the toggle; the desktop menu follows the system language (English or Turkish).
